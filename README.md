## Задание
В этой работе вам нужно будет реализовать программу, которая будет собирать данные о самолетах в воздушных пространствах
тех стран, которые вы выберете.

Чтобы получить географические координаты стран, будем использовать API nominatim.openstreetmap.org, а чтобы получить
информацию о самолетах — API opensky-network.org.

Код класса, реализующего получение такой информации вы можете посмотреть по ссылке.

Пример ответа от nominatim.openstreetmap.org можно посмотреть по ссылке.

В ответе нас интересует параметр boundingbox — координаты южной, северной, западной и восточной точки страны.

Чтобы было проще, посмотрите, как boundingbox выглядит на карте (в примере использована Канада):

Да, в периметр попадает часть США и Гренландии, но, к сожалению, в мире нет прямоугольных стран, а для наших целей такой
уровень точности вполне подойдет. Осталось только получить информацию о самолетах, в данный момент находящихся на земле
или в воздухе в пространстве выбранной страны.

Это уже реализовано в коде файла api.py с помощью запроса к opensky.network.org. Вот пример ответа, который записывается
в переменную
self.aeroplanes
в файле api.py: opensky-network.response.json.

## Требования к реализации
## Шаг 1: создание абстрактного класса для работы с API
Создать абстрактный класс для работы с API сервисов nominatim.openstreetmap.org и opensky-network.org.
Реализовать класс, наследующийся от абстрактного класса, для работы с платформами nominatim.openstreetmap.org и
opensky-network.org.
Класс должен уметь подключаться к API и получать географические координаты стран и информацию о самолетах, находящихся в
воздушном пространстве этих стран.

## Шаг 2: создание класса для работы с информацией о самолетах
Создать класс для работы с информацией о самолетах.
В этом классе самостоятельно определить атрибуты: страна регистрации, позывной, скорость полета, высота полета и так
далее (всего не менее четырех атрибутов).
Пример ответа с подробным объяснением значения каждого атрибута можно посмотреть тут: opensky-network.response.json.

Класс должен поддерживать методы сравнения самолетов между собой по скорости и высоте, валидировать данные, которыми
инициализируются его атрибуты.

## Шаг 3: Создание классов для работы с файлами
Определить абстрактный класс, который обязывает реализовать методы для добавления информации о самолете в файл,
получения данных из файла по указанным критериям и удаления информации о самолетах.
Создать класс для сохранения информации о самолетах в JSON-файл. Дополнительно, по желанию, можно реализовать классы для
работы с другими форматами: CSV- или Excel-файлом, с TXT-файлом.
Данный класс выступит в роли основы для коннектора, заменяя который (класс-коннектор), можно использовать в качестве
хранилища одну из баз данных или удаленное хранилище со своей специфической системой обращений.

В случае если какие-то из методов выглядят не используемыми для работы с файлами, то не стоит их удалять. Они пригодятся
для интеграции к БД. Сделайте заглушку в коде.

## Шаг 4: создание функции для взаимодействия с пользователем
Создать функцию для взаимодействия с пользователем. Функция должна взаимодействовать с пользователем через консоль.

Возможности этой функции должны быть следующими:

Ввести название страны для запроса информации о самолетах из opensky-network.org.
Получить топ N самолетов по высоте полета (N запрашивать у пользователя).
Получить самолеты по стране их регистрации.
Помимо этого функционала, можно придумать дополнительные возможности, которые покажутся удобными.

## Шаг 5: объединение компонентов
Объединить все классы и функции в единую программу.
Покрыть описанный функционал тестами.
Требования к реализации в парадигме ООП
Абстрактный класс и классы для работы с API должны быть реализованы в соответствии с принципом наследования.
Класс для работы с самолетами должен быть реализован в соответствии с принципом инкапсуляции и поддерживать методы
сравнения самолетов между собой по скорости и высоте полета.
Классы и другие сущности в проекте должны удовлетворять минимум первым двум требованиям принципов SOLID.
